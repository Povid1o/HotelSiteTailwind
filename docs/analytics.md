# Аналитика: Яндекс Метрика

Сайт отправляет данные в Яндекс Метрику, а в админке есть раздел «Аналитика»,
где они собраны в одну сводку: ключевые показатели, цели, источники, страницы
входа, устройства, города, время суток и автоматические наблюдения-гипотезы.

## Как это устроено

- **Сбор.** `hotel-project/src/utils/metrika.ts` загружает счётчик только после
  того, как посетитель нажал «Принять» в баннере cookie. Просмотры отправляются
  при каждой смене страницы (сайт — SPA), админка и вход не учитываются.
- **Цели** (JS-события), которые отправляет сайт:

  | Идентификатор | Когда |
  |---|---|
  | `booking_open` | открыли бронирование (меню, карточка номера) |
  | `phone_click` | клик по ссылке `tel:` |
  | `email_click` | клик по ссылке `mailto:` |
  | `whatsapp_click` | переход в WhatsApp |
  | `telegram_click` | переход в Telegram |

- **Отчёты.** Бэкенд (`HotelSiteBackend/utils/metrika.js`) сам запрашивает
  Reporting API Метрики — токен не попадает в браузер. Сводка кешируется на
  10 минут, кнопка «Обновить» срабатывает не чаще раза в минуту.
  Эндпоинт: `GET /api/analytics/dashboard?days=7|30|90`, только для администратора.

## Настройка

1. **Счётчик.** На metrika.yandex.ru создайте счётчик для домена сайта, включите
   Вебвизор. Номер счётчика — `YM_ID`.
2. **Цели.** В счётчике → «Цели» → «Добавить цель» → тип «JavaScript-событие»;
   создайте пять целей с идентификаторами из таблицы выше.
3. **Токен для отчётов.**
   - На oauth.yandex.ru создайте приложение, платформа «Веб-сервисы»,
     Redirect URI — `https://oauth.yandex.ru/verification_code`.
   - Доступ: «Яндекс Метрика → Получение статистики, чтение параметров своих и
     доверенных счётчиков» (`metrika:read`).
   - Откройте `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID приложения>`
     под аккаунтом, у которого есть доступ к счётчику, и скопируйте токен — это `YM_TOKEN`.
   - Токен действует год; когда он истечёт, раздел покажет ошибку «Метрика отклонила токен» —
     получите новый тем же способом.
4. **Сервер.** Добавьте в `.env` рядом с `docker-compose.yml`:

   ```
   YM_ID=12345678
   YM_TOKEN=y0_...
   ```

   и пересоберите контейнеры (`docker-compose up --build -d` — это делает обычный деплой).
   `YM_ID` встраивается во фронтенд при сборке, поэтому без пересборки счётчик на сайте не появится.
5. **TravelLine.** В личном кабинете TravelLine укажите номер счётчика — тогда
   оплаченные бронирования попадут в Метрику как электронная коммерция и появятся
   в разделе плиткой «Бронирования (TravelLine)».
6. **Политика конфиденциальности.** Упомяните на странице `/Privacy`, что сайт
   использует cookie и Яндекс Метрику.

## Наблюдения и гипотезы

Блок формируется правилами в `buildInsights` (`HotelSiteBackend/utils/metrika.js`):
изменение трафика к прошлому периоду, устройства с повышенными отказами, доля
смартфонов, лучший и слабый источник по конверсии в бронирование, страница входа
с высокими отказами, соотношение контактов и бронирований, пиковый час. При
малом числе визитов (< 50) выводится только предупреждение о недостатке данных.
Пороги — в коде, их легко подстроить.

## Проверка без настоящего счётчика

`HotelSiteBackend/test/fixtures/fakeMetrika.js` отвечает в формате Reporting API.
Тесты (`npm test` в `HotelSiteBackend`) собирают по нему полную сводку.
Для ручной проверки можно поднять его как HTTP-сервер и указать бэкенду
`YM_API_BASE=http://localhost:<порт>`.

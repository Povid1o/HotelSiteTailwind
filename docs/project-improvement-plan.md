# План стабилизации и развития проекта

Дата сверки: 2026-08-03. План основан на проверке текущей ветки
`codex/stabilize-admin`, исходного макета V4 и независимого аудита.

## Уже сделано

- Редактирование и загрузка контента ограничены авторизованным администратором.
- Регистрация больше не принимает роль из запроса; пароль хешируется с cost 12.
- Загрузка файлов ограничена ролями, расширениями, заявленным MIME и размерами.
- Схема БД больше не синхронизируется и не сидируется при каждом старте.
- Сохранение секций страниц переведено на точечные PATCH-запросы с очередью.
- В V4 выровнены шапка, hero, события, дегустационная плашка и футер.
- Контракт кнопок V4: радиус 8 px; hover — полупрозрачная заливка без исчезновения текста.

## Ближайший этап — безопасность и надёжность

| Приоритет | Работа | Основание и результат |
|---|---|---|
| P0 | Ротировать JWT-ключ и пароль PostgreSQL во всех средах | Старые значения могли попасть в историю Git. Потребуется одновременно обновить секреты развёртывания; все текущие сессии админов будут завершены. |
| P0 | Ограничить запросы к `/api/user/login` | Защита от перебора пароля и дешёвого DoS через bcrypt. Добавить `express-rate-limit`, отдельные лимиты на IP и понятный 429-ответ. |
| P0 | Исправить CORS на уровне nginx | Сейчас nginx добавляет `Access-Control-Allow-Origin: *`, обходя настройку Express. Оставить единую политику в бэкенде либо прокси, но не в обоих. |
| P1 | Добавить `helmet` и CSP | Базовые security-заголовки, запрет встраивания админки во фрейм, контролируемые источники скриптов/карт. CSP вводить в report-only режиме, затем ужесточить. |
| P1 | Обрабатывать истёкший токен в axios | Единый 401-интерцептор: очистить локальную сессию, показать сообщение и перевести на `/login`, чтобы сохранения не «падали молча». |
| P1 | Жёстко отклонять превышенные загрузки | Включить `abortOnLimit`, проверять `uploadedFile.truncated`, гарантированно очищать временный файл. |
| P1 | Валидировать фактический тип медиа | Проверять сигнатуру файла (magic bytes) для изображений и видео, а не только MIME, переданный браузером. |
| P2 | Перевести с JWT в localStorage на httpOnly cookie + CSRF | Это уменьшит последствия XSS. Требует согласованной переработки login/logout и фронтенд-запросов, поэтому выполняется отдельным этапом после 401/CSP. |
| P2 | Убрать устаревшие `/api/type`, `/api/clase`, `/api/product` | Сначала вывести из употребления `productAPI.tsx`, затем удалить маршруты, модели и миграции. Удалять сейчас нельзя: вызовы в проекте ещё есть. |
| P2 | Исправить `.gitignore` для манифестов зависимостей | Убрать исключения для отслеживаемых `package.json` и lock-файла, чтобы обновления зависимостей не терялись. |

## Следующий этап — скорость публичного сайта

| Приоритет | Работа | Результат |
|---|---|---|
| P1 | Убрать глобальную блокировку приложения | Сейчас `App.tsx` ждёт блюда, номера, страницы, вина и события до первого рендера. Главная должна рендериться сразу, а данные загружаться по маршруту. |
| P1 | Убрать второй router и добавить guard `/admin` | Один router исключит полный remount при изменении авторизации и сохранит состояние интерфейса. |
| P2 | Оптимизировать изображения | Инвентаризация 36 МБ локальных ассетов, затем WebP/AVIF, `picture/srcset`, lazy-loading и лимиты размеров при загрузке. |
| P2 | Сделать прямую раздачу `/static` через Caddy | Сейчас путь идёт через Caddy → nginx → backend. После настройки Caddy медиа будут отдаваться с корректным кешированием без лишних прокси-переходов. |
| P2 | Убрать автосохранение на каждый символ | Привести старые редакторы к модели draft/dirty → «Сохранить»/«Отменить» либо debounce 600 мс. Это снизит нагрузку и сделает поведение предсказуемым. |
| P3 | Ограничить и постранично выдавать API-коллекции | Начать с фильтра `pages?path=…`, затем пагинация каталогов. Пока объём БД мал, поэтому это не блокирует запуск. |
| P3 | Приостановить фоновые проверки во вкладке не в фокусе | `AdminStatusBadge` не должен выполнять ping раз в 15 секунд при скрытой вкладке. |
| P3 | Очистить production-логи | Удалить диагностические `console.log` из клиентских storages/API. |
| Отложено | Переезд CRA на Vite | Полезен для скорости разработки, но не заменяет оптимизацию загрузки и медиа. Выполнять отдельной миграцией после стабилизации функциональности. |

## Порядок выполнения

1. P0 безопасности — требует согласования момента ротации секретов.
2. P1 производительности и админского UX — можно внедрять без изменения публичного контента.
3. P2 защиты медиа и оптимизации изображений — с тестовыми файлами и обратимой миграцией.
4. Архитектурные отложенные работы — отдельными небольшими релизами.

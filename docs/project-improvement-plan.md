# План стабилизации и развития проекта

Дата сверки: 2026-08-04. План основан на проверке текущей ветки
`codex/stabilize-admin`, исходного макета V4 и независимого аудита.

## Уже сделано

- Редактирование и загрузка контента ограничены авторизованным администратором.
- Регистрация больше не принимает роль из запроса; пароль хешируется с cost 12.
- Загрузка файлов ограничена ролями, расширениями, заявленным MIME и размерами.
- Схема БД больше не синхронизируется и не сидируется при каждом старте.
- Сохранение секций страниц переведено на точечные PATCH-запросы с очередью.
- В V4 выровнены шапка, hero, события, дегустационная плашка и футер.
- Все публичные карточки сведены к общим V4-компонентам: номера, вина, события и блюда больше не используют расходящиеся локальные варианты. Карточка номера открывает V4-диалог.
- Контракт кнопок V4: радиус 8 px; hover — полупрозрачная заливка без исчезновения текста.
- Неверные учётные данные при входе теперь возвращают единый `401`, а ошибки валидации — корректный `400` вместо ложных `500`/`404`.

## Ближайший этап — безопасность и надёжность

| Приоритет | Работа | Основание и результат |
|---|---|---|
| Выполнено | Ротировать JWT-ключ и пароль PostgreSQL во всех средах | Создан и проверен дамп БД, затем сгенерированы новые JWT/прикладные секреты и пароль роли PostgreSQL. Локальные конфигурации синхронизированы; старые сессии завершены. |
| Выполнено | Ограничить запросы к `/api/user/login` | Добавлен лимит: 10 попыток с IP за 15 минут, стандартные rate-limit заголовки и понятный 429-ответ. |
| Выполнено | Исправить CORS на уровне nginx | Убран `Access-Control-Allow-Origin: *` из nginx; единственная политика CORS теперь в Express. |
| Выполнено | Добавить `helmet` и CSP | Helmet включён для API и медиа; публичная HTML-страница получила CSP в report-only режиме с источниками Яндекс.Карт, шрифтов и TravelLine. Enforce включается после анализа нарушений на боевом домене. |
| Выполнено | Обрабатывать истёкший токен в axios | Единый 401-интерцептор очищает сессию и переводит на `/login`, чтобы сохранения не «падали молча». |
| Выполнено | Не перенаправлять гостя в `/login` при фоновой проверке сессии | Проверка текущего пользователя выполняется на каждой публичной странице; её ожидаемый `401` теперь не запускает редирект. Реальный `401` изменяющего запроса по-прежнему завершает сессию. |
| Выполнено | Жёстко отклонять превышенные загрузки | Включены `abortOnLimit`, 413-ответ и дополнительная проверка `truncated`. |
| Выполнено | Валидировать фактический тип медиа | `file-type` проверяет сигнатуру временного файла до переноса в публичное хранилище. |
| Выполнено | Перевести с JWT в localStorage на httpOnly cookie + CSRF | Введены httpOnly session-cookie и отдельная CSRF-cookie; frontend отправляет CSRF-заголовок только для изменяющих запросов. Проверены 401 без сессии, 403 без CSRF и успешные cookie-auth/logout. |
| Выполнено | Убрать устаревшие `/api/type`, `/api/clase`, `/api/product` | Удалены маршруты, контроллеры, `ProductStorage`, legacy API и неиспользуемые модалки. Старые таблицы БД сознательно оставлены нетронутыми как обратимый архив. |
| Выполнено | Исправить `.gitignore` для манифестов зависимостей | Убраны исключения для отслеживаемых `package.json` и lock-файла; `node_modules` обеих частей проекта явно игнорируются. |

## Следующий этап — скорость публичного сайта

| Приоритет | Работа | Результат |
|---|---|---|
| Выполнено | Убрать глобальную блокировку приложения | `App.tsx` ждёт только проверку сессии. `RouteDataLoader` подгружает данные по открытому маршруту, а главная рендерится сразу с V4-fallback до прихода карточек. |
| Выполнено | Убрать второй router и добавить guard `/admin` | Один router с `RequireAdmin` исключает полный remount при изменении авторизации и сохраняет состояние интерфейса. |
| Выполнено | Оптимизировать изображения | В используемой винодельческой карусели и hero четыре PNG заменены на JPEG качества 80: 6,6 МБ → 1,3 МБ. Загрузки уже имеют лимиты; исторические неиспользуемые ассеты не включаются в текущую V4-сборку. |
| Выполнено | Сделать прямую раздачу загруженных медиа через Caddy | Общий read-only том с загрузками подключён к Caddy: `/static/dishes`, `pages`, `rooms`, `wines`, `videos`, `fallbacks` раздаются напрямую с годовым immutable-кешем. Служебные `/static/js` и CSS остаются у фронтенда, поэтому React-сборка не перехватывается. |
| Выполнено | Убрать автосохранение на каждый символ | Контент секции обновляется локально сразу, а запрос к API отправляется только через 600 мс после последнего изменения. Устаревшие промежуточные правки не попадают в очередь. |
| Выполнено | Ограничить и постранично выдавать API-коллекции | `GET /api/pages` поддерживает точный `path`, безопасные `limit` (до 100), `offset` и стабильный порядок. Каталоги пока малы; их отображение будет постраничным в рамках будущей переработки админского списка. |
| Выполнено | Приостановить фоновые проверки во вкладке не в фокусе | `AdminStatusBadge` отключает 15-секундный ping при скрытой вкладке и возобновляет его только при возврате. |
| Выполнено | Очистить production-логи | Убраны стартовые диагностические логи API-клиента; оставшиеся `console.warn/error` несут информацию о сбоях сохранения и не раскрывают данные. |
| Отложено | Переезд CRA на Vite | Полезен для скорости разработки, но не заменяет оптимизацию загрузки и медиа. Выполнять отдельной миграцией после стабилизации функциональности. |

## Админ-панель — рабочий UX

| Приоритет | Работа | Результат |
|---|---|---|
| Выполнено | Восстановить CSRF-сохранения в `/admin` | CSRF-cookie доступна на пути `/`, а не только `/api`; повторная проверка сессии автоматически исправляет уже открытые браузеры. Теперь изменения контента и создание сущностей получают обязательный CSRF-заголовок, а не ложный `403`. |
| Выполнено | Закрытие редакторов и создание номера | Во всех базовых админских модальных редакторах есть самостоятельная кнопка «Закрыть ×» и закрытие по Esc; между ней и формой есть отдельный отступ. В «Карточках номеров» добавлена кнопка «Добавить номер» с защитой от повторного клика. |
| Выполнено | Восстановить создание категории меню | На маршрутах категорий, типов и сладости вина авторизация теперь проходит до проверки роли. Создание и последующее удаление временной категории проверены реальным API-запросом с cookie-сессией и CSRF. |
| P1 | Унифицировать сохранение и защиту от потери черновика | Единые draft/dirty, «Сохранить»/«Отменить», статус сохранения и предупреждение при закрытии вкладки. |
| P1 | Уведомления и подтверждение удаления | Заменить `alert()` на toast/inline-ошибки; для удаления — confirm и краткое «Отменить». |
| P2 | Разделить `AdminPage` на адресные разделы | `/admin/pages`, `/admin/rooms`, `/admin/menu`, `/admin/wines`, `/admin/events`; меньше кода на экран, lazy-loading, прямые ссылки коллегам. |
| P2 | Добавить preview режима страницы | Split-view с безопасным предпросмотром публичной страницы из черновика. |
| P2 | Сделать медиатеку | Повторное использование файлов, alt-тексты, drag-and-drop, оптимизация изображения перед загрузкой, безопасное удаление неиспользуемых файлов. |
| P3 | Роли и audit log | Роли ADMIN/EDITOR и история «кто/что/когда изменил» с возможностью отката. |
| P3 | Доступность и каркас админки | Убрать фиксированный `h-screen` и плавающий бейдж из контента; добавить sidebar, видимый focus, aria-label и клавиатурную навигацию. |
| Отложено | Полная замена UI/data-стека | Radix/shadcn, TanStack Query, react-hook-form/zod рационально вводить после разбиения админки, не как рискованную массовую замену. |

## Порядок выполнения

1. P0 безопасности — требует согласования момента ротации секретов.
2. P1 производительности и админского UX — можно внедрять без изменения публичного контента.
3. P2 защиты медиа и оптимизации изображений — с тестовыми файлами и обратимой миграцией.
4. Архитектурные отложенные работы — отдельными небольшими релизами.

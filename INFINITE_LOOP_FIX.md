# Исправление бесконечного цикла загрузки

## ❌ Проблема: Бесконечная загрузка

**Симптомы**:
- Админская страница зависает на экране "Загрузка..."
- Страница никогда не загружается полностью
- В консоли браузера повторяющиеся логи загрузки

**Корневая причина**:
В `AdminPage.tsx` были **два useEffect** (строки 105-172 и 174-180), которые оба:
1. Загружали одни и те же данные
2. Имели одинаковые зависимости: `[dish, hotel, pageContent, wine]`

## 🔄 Как это вызывало бесконечный цикл:

```
1. Компонент монтируется
   ↓
2. Оба useEffect срабатывают → загружают данные
   ↓
3. Stores обновляются (dish.setLoading(false), dish.setDishes(...))
   ↓
4. dish, hotel, pageContent, wine изменились!
   ↓
5. Оба useEffect срабатывают СНОВА (из-за зависимостей)
   ↓
6. Загрузка начинается снова
   ↓
7. Stores обновляются снова
   ↓
8. useEffect срабатывают снова
   ↓
9. ∞ БЕСКОНЕЧНЫЙ ЦИКЛ ∞
```

## ✅ Решение:

**До исправления**:
```typescript
// Первый useEffect (строки 105-172)
useEffect(() => {
  loadData(); // Загружает dish, hotel, pageContent, wine
}, [dish, hotel, pageContent, wine]); // ← Триггерится при изменении stores

// Второй useEffect (строки 174-180) - ДУБЛИКАТ!
useEffect(() => {
  dish.loadDishes();
  hotel.loadRooms();
  pageContent.loadPageContent();
  wine.loadWines();
}, [dish, hotel, pageContent, wine]); // ← Триггерится при изменении stores
```

**После исправления**:
```typescript
// Только один useEffect
useEffect(() => {
  loadData(); // Загружает dish, hotel, pageContent, wine
}, []); // ← Пустые зависимости - загружать ТОЛЬКО при монтировании
```

## 📋 Изменения:

1. ✅ Удален второй (дублирующийся) useEffect (строки 174-180)
2. ✅ Изменены зависимости первого useEffect с `[dish, hotel, pageContent, wine]` на `[]`
3. ✅ Добавлен комментарий `eslint-disable-next-line` для подавления предупреждения о пустых зависимостях

## 💡 Почему пустые зависимости [] - это правильно:

1. **Stores - это singleton объекты**: `dish`, `hotel`, `pageContent`, `wine` создаются один раз в `index.tsx` и никогда не пересоздаются
2. **MobX observer отслеживает изменения**: Компонент обернут в `observer()`, поэтому он автоматически перерендеривается при изменении данных в stores
3. **Загрузка нужна только один раз**: При монтировании компонента мы загружаем данные один раз, дальше все обновления происходят через MobX

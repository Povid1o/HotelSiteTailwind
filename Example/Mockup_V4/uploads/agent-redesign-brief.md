# Бриф проекта и техническое задание на полный редизайн

Дата актуализации: 2 августа 2026.  
Статус: рабочий бриф для следующего агента/дизайнера. Это не маркетинговый текст и не источник паролей, а карта продукта, ограничений и ожидаемого результата.

---

## 1. Коротко о проекте

Это сайт гостинично-винодельческого пространства в Абрау-Дюрсо/Черноморском регионе. В одном цифровом продукте соединены:

- проживание в отеле и карточки номеров;
- винодельня и ассортимент вин;
- ресторанное меню;
- события, экскурсии и впечатления;
- производственный центр/история производства;
- публичная часть и закрытая административная панель.

Рабочий образ бренда — **«Террасы»**: место, куда приезжают не за одной услугой, а за неторопливым маршрутом через пейзаж, вино, гастрономию и отдых. Это не городской luxury-отель и не ярмарочный туристический парк. Нужна спокойная, взрослая, современная гостеприимная подача с ощущением терруара и личного времени.

### Целевой пользователь

1. Пара 28–50 лет, которая выбирает короткую поездку на выходные и хочет быстро понять атмосферу, номера и как забронировать.
2. Гость винодельни/ресторана, который ищет событие, дегустацию, винную линейку или маршрут.
3. Компания/организатор мероприятия, которой нужны пространство, сценарий и понятный контакт.
4. Администратор контента без технического опыта: должен менять тексты, изображения, видео, номера, блюда, вина и события без закрытия модального окна или непредсказуемой потери данных.

### Главная продуктовая задача

За 15–30 секунд ответить на три вопроса: **куда я попал, зачем мне сюда ехать и что сделать дальше**. Главный CTA — перейти к выбору номера/бронированию; вторичные — посмотреть впечатления, вино, ресторан или события.

## 2. Текущая реализация

### Стек

| Слой | Реализация |
| --- | --- |
| Frontend | React 18, TypeScript, React Router, MobX |
| UI/стили | Tailwind CSS, Flowbite React, Material Tailwind, CSS-модули/обычные CSS-файлы |
| Движение и медиа | Framer Motion, Swiper, React Player, Yandex Maps |
| Backend | Node.js + Express |
| Данные | PostgreSQL + Sequelize |
| Медиа | локальные статические папки backend (`rooms`, `pages`, `dishes`, `wines`, `videos`) |
| Развёртывание | Docker Compose: PostgreSQL, backend, frontend, Caddy |

### Основные маршруты публичной части

| Маршрут | Назначение |
| --- | --- |
| `/` | главный экран/развилка продукта |
| `/Hotel` | отель, номера, бронирование |
| `/Vinery` | винодельня и история/производство |
| `/Restaurant` | ресторан и меню |
| `/Events` | категории мероприятий |
| `/Events/:categorie` | листинг событий категории |
| `/ProductionCenter` | производственный центр |
| `/Shop`, `/Shop/:productId` | витрина вина/товара (не гарантировать полноценный e-commerce без отдельного решения) |
| `/login` | вход администратора |
| `/admin` | административная панель только для роли `ADMIN` |

### Что редактируется через админ-панель

- секции страниц: hero, тексты, галереи, изображения, видео, сервисы и этапы производства;
- номера: название, цены, удобства, фотографии, описание, активность;
- меню: категории и блюда;
- вина: тип, сладость, цена, описание, фотографии;
- события и их категории.

**Обязательное правило:** новый визуальный слой не должен превращать эти данные в захардкоженный контент. Любой дизайн-компонент обязан работать с существующими данными, пустыми состояниями и временно отсутствующими изображениями.

## 3. Состояние качества и технические ограничения

### Уже исправлено в текущей рабочей ветке

- административные mutation-маршруты и загрузка медиа ограничены ролью `ADMIN`;
- регистрация администратора не публична;
- сохранение контента страниц выполняется по секциям и последовательно;
- карточки номеров, блюд, вин и мероприятий получают очереди сохранения, оптимистичное состояние и отображение «сохраняем/ошибка»;
- закрытие редактора не отменяет изменение, находящееся в debounce-окне;
- исправлен контракт обновления изображений: отсутствие поля `images` не должно удалять существующую галерею, а явный пустой массив означает очистку;
- фронтенд production-build проходит; server tests проходят.

### Остающиеся риски, которые дизайн-агент не должен усугублять

1. В кодовой базе есть накопленные ESLint и TypeScript-предупреждения. Не маскировать их отключением правил; не добавлять `any` без крайней необходимости.
2. Сервер сейчас использует `sequelize.sync()` при старте. Не полагаться на автоматическое изменение схемы БД; для новых полей сначала согласовать миграции.
3. Значения подключений/секреты в старых конфигурациях требуют отдельной безопасной ротации. Никогда не выводить, не копировать и не публиковать секреты.
4. Соединение с локальной PostgreSQL на момент брифа не подтверждено: сервер отвечает, но сохранённый в проекте пароль для роли `postgres` отклонён. Это не задача дизайна.
5. Медиа имеют ограничения: изображения JPEG/PNG/WebP до 10 МБ; видео MP4/WebM до 100 МБ. Не проектировать интерфейс, требующий не поддерживаемых форматов.
6. Сайт должен оставаться usable при медленном интернете: большие hero-видео — опциональны, фото должны иметь `loading="lazy"` вне первого экрана, нужна аккуратная деградация без медиа.

## 4. Аудит текущего визуального языка

### Как сайт ощущался до редизайна

- Бордовая винодельческая палитра (`#80143c`) на белом/кремовом фоне.
- Основной шрифт — **Bitter**; один шрифт одновременно использовался для навигации, текста и крупных заголовков.
- Много скруглённых белых карточек с тенями, видимые Swiper-галереи, стандартная Tailwind/Flowbite-пластика.
- Hero-секции со сплошными фотографиями и крупными белыми заголовками.
- Визуальная подача фрагментарна: разные страницы ощущаются как набор отдельно разработанных секций.

Это даёт понятный «винный» вайб, но не формирует собственный характер. В сочетании с похожей информационной архитектурой возникло впечатление слишком близкой стилизации под Château Pinot. Это нужно полностью исключить.

### Черновой дизайн-фундамент, уже внесённый в ветку

Это **не завершённый редизайн**, а только направление для обсуждения:

| Токен | Значение | Роль |
| --- | --- | --- |
| `ink` | `#19312F` | глубокий хвойный фон, текст, footer |
| `main_theme` | `#1F4D4A` | основной брендовый зелёный |
| `sand` | `#F5F2EA` | тёплый известняковый фон |
| `clay` | `#C7774D` | сдержанный терракотовый акцент и CTA |
| `mist` | `#DCE5DE` | мягкая ботаническая подложка |
| display | Cormorant Garamond | только эмоциональные крупные заголовки |
| body | Manrope | навигация, интерфейс, основной текст |

Это направление нужно воспринимать как стартовую гипотезу. Его можно скорректировать после утверждения макета, но нельзя возвращаться к бордовому «шато»-коду как к решению по умолчанию.

## 6. Техническое задание агенту на дизайн-код и полный редизайн

### Роль агента

Ты — ведущий product designer и senior frontend engineer. Твоя цель — создать самостоятельный, цельный дизайн-код и внедрить его во все основные страницы React-сайта, сохранив функциональность, динамический контент и админ-редактирование.

### Выбор стартовых дизайн-систем в Claude

Выбрать **ровно две** системы: **Classical + Organic**.

| Система | Разрешённая роль |
| --- | --- |
| Classical | Главный каркас: редакционная иерархия, спокойная премиальная подача, масштаб serif-заголовков, дисциплина сетки и воздуха. |
| Organic | Второй слой: природная тактильность, асимметричные медиа-композиции, мягкие ботанические подложки, ощущение местности и маршрута. |
| Modernist | **Не выбирать как систему.** Допустим только как микроприём: один контрастный терракотовый/красно-глиняный акцент в CTA, индикаторе или тонкой линии. |

Нельзя механически смешивать карточки, кнопки, шрифты и сетки из двух систем. Иерархия всегда такая: **Classical задаёт типографику и структуру, Organic — материал, настроение и композицию медиа**.

Фиксированные переопределения поверх пресетов Claude:

- display: `Cormorant Garamond`; основной текст и UI: `Manrope` (не Lora и не Caprasimo);
- базовые цвета: `#19312F`, `#1F4D4A`, `#F5F2EA`, `#DCE5DE`, `#C7774D`;
- красный/терракотовый занимает не более одного акцентного действия в пределах экрана и не становится фоном сайта;
- никакого бордового винного монохрома, золотой «роскоши», геральдики или визуального языка «шато»;
- при конфликте пресета и этого брифа приоритет у брифа.

### Результат, который нужно получить

1. Новый визуальный язык, который нельзя спутать с Château Pinot или прямыми референсами.
2. Единая дизайн-система: токены, типографика, сетка, отступы, поверхности, компоненты, интерактивные состояния.
3. Полный редизайн публичной части, начиная с главной, с последующим применением системы к отелю, винодельне, ресторану, событиям и производству.
4. Сохранённый и предсказуемый функционал админ-панели.
5. Адаптивность 320–1440+ px, доступность и приемлемая производительность.

### Продуктовая концепция

Сайт должен вести гостя по маршруту:

`природа/атмосфера → проживание → вкус/винодельня → события/маршрут → бронирование или контакт`.

Главная страница — не каталог и не набор рекламных баннеров. Это короткая редакционная история с ясными развилками. На каждой странице один основной CTA и не более одного вторичного действия в пределах первого экрана.

### Визуальные принципы

- **Контраст:** тёмный хвойный/графитовый фон против светлого тёплого известняка; терракота — редкий функциональный акцент, не заливка всего интерфейса.
- **Типографика:** эмоциональный serif только для заголовков, нейтральный sans для текста и интерфейса. Не применять display-шрифт к длинным абзацам, таблицам и формам.
- **Сетка:** desktop 12 колонок, tablet 8, mobile 4; контейнер `max-width` 1200–1280 px; горизонтальные поля не меньше 20 px на mobile.
- **Ритм:** базовая шкала 4/8 px; крупные секции 80–144 px; больше пустого пространства, меньше «плиток».
- **Изображения:** живой ландшафт, натуральные материалы, детали производства и гостеприимства. Избегать стокового лоска, чрезмерно постановочных людей и повторяющихся бутылок на каждом экране.
- **Поверхности:** скругление 2–12 px по смыслу; избегать большого количества одинаковых `rounded-xl` карточек и тяжёлых теней. Разделять блоки цветом, ритмом, линией и кадрированием.
- **Анимация:** короткая, спокойная, служебная. Поддерживать `prefers-reduced-motion`. Не использовать бесконечные декоративные эффекты и не скрывать контент за анимацией.

### Состав дизайн-кода

Создать и документировать:

```text
color: ink / forest / sand / mist / clay / white / error / success
type: display-xxl..display-sm / body-lg..body-sm / label / button
space: 4, 8, 12, 16, 24, 32, 48, 64, 80, 112, 144
radius: 2, 8, 12
elevation: none / soft (только для overlay и форм)
motion: fast 160ms / base 240ms / slow 420ms
breakpoints: 320, 640, 768, 1024, 1280, 1536
```

Компоненты, которые необходимо стандартизировать:

- `SiteHeader` и мобильное меню;
- primary/secondary/text button и link-with-arrow;
- section heading (eyebrow + heading + optional text/CTA);
- media card и content card;
- room card;
- event card;
- wine card/таблица ассортимента;
- gallery/mosaic;
- booking CTA/интеграционный блок TravelLine;
- input, select, textarea, upload state;
- status badge (`Сохраняем`, `Сохранено`, `Ошибка`);
- modal/drawer;
- footer;
- skeleton, empty state и error state.

Нельзя держать дизайн-код в десятках дублирующихся строк Tailwind. Разрешается Tailwind, но повторяемые паттерны должны жить в токенах, компонентах и `@layer components`/общих утилитах.

### Страница за страницей

#### Главная (`/`)

1. Hero: крупное атмосферное изображение/видео, логичный контраст, headline, краткое позиционирование, primary CTA. Не делать копию split-screen Château Pinot.
2. Блок «почему остаться»: редакционная композиция текста и 1–3 фотографий.
3. Номера: две/несколько динамических карточек из `hotel.rooms` с ценой и переходом.
4. Вино/винодельня: не каталог бутылок, а история места + entry point в ассортимент/экскурсии.
5. Ресторан или сезонное предложение.
6. События/маршруты.
7. Финальный booking CTA и footer.

#### Отель (`/Hotel`)

- информация должна быть легче карточного каталога: сильная hero-композиция, фильтруемые/понятные номера, ясные детали и CTA;
- карточка номера: кадр, название, краткая характеристика, цена «от», действие;
- extended/modal-представление должно быть доступно с клавиатуры и сохранять контекст;
- не терять подключение TravelLine.

#### Винодельня и производство (`/Vinery`, `/ProductionCenter`)

- строить вокруг процесса, территории, материалов и времени;
- использовать timeline/этапы только если они содержательно помогают, не ради украшения;
- разделять образовательную информацию и коммерческие CTA;
- видео поддерживать как необязательное прогрессивное улучшение.

#### Ресторан (`/Restaurant`)

- сделать меню читаемым: категории, названия, вес/описание/цена, мобильный ритм;
- фотография поддерживает блюдо, а не заменяет информацию;
- оставить данные `DishStorage` и сценарии админ-редактирования без изменения контрактов.

#### События (`/Events`, `/Events/:categorie`)

- сначала дать выбрать повод/тип события, затем — конкретные карточки;
- карточка должна показывать заголовок, дату/период при наличии, краткий контекст, изображение и CTA;
- предусмотреть пустое состояние «Скоро появятся новые события».

#### Вино/витрина (`/Vinery`, `/Shop`)

- структурировать ассортимент по типу/сладости без тяжёлой магазинной стилистики;
- цена и ключевые характеристики должны оставаться читаемыми;
- если онлайн-оплата не реализована, не имитировать корзину/checkout.

#### Админ-панель (`/admin`)

- не является маркетинговой страницей: приоритет — ясность, контраст, компактность, состояние операции;
- оставить таблицы/редакторы функциональными;
- использовать новый дизайн-код умеренно: цвет, типографика, кнопки, статусы, modal; не превращать интерфейс в декоративный лендинг;
- сохранить видимые состояния `Сохраняем…`, `Ошибка сохранения`, `Сохранено`.

### Доступность и качество

- Семантические `header`, `nav`, `main`, `section`, `footer`; один `h1` на страницу.
- Все изображения имеют осмысленный `alt` или пустой `alt` для декора.
- Контраст текста минимум WCAG AA; CTA не различаются только цветом.
- Меню и модальные окна работают с клавиатуры: focus visible, Esc, фокус-ловушка для modal.
- Не использовать `a href="#"` для кнопок.
- Не использовать inline-стили для повторяемого визуального поведения.
- Не ломать `prefers-reduced-motion`, не делать важный контент недоступным без hover.

### Производительность

- Первая hero-картинка: адаптивные источники/WebP, разумный размер; не загружать видео до явной необходимости.
- Галереи и нижефолдовые медиа — `loading="lazy"`.
- Избежать подключения CSS-фреймворков через `<link>` внутри React-компонентов.
- Не добавлять тяжёлую UI-библиотеку ради одного компонента.
- Проверить mobile Lighthouse до и после: не ухудшить LCP/CLS относительно исходного состояния.

### Порядок работы

1. Прочитать этот файл, существующие маршруты, storage и контракты API.
2. Зафиксировать короткий wireframe главной и показать его на согласование до массовой вёрстки.
3. Создать токены и базовые компоненты, не меняя API/БД.
4. Внедрить главную страницу, показать screenshot desktop + mobile.
5. Применить систему к отелю, винодельне, ресторану, событиям, производству.
6. Адаптировать админ-панель функционально, без регрессий сохранения.
7. Прогнать `npm run build`, backend tests и ручной smoke-test: загрузка страниц, login, создание/редактирование/удаление тестовой сущности в безопасной среде.
8. Отчитаться: список изменённых файлов, screenshots, проверенные сценарии, известные ограничения.

### Критерии приёмки

- Новый сайт визуально не воспринимается как копия Château Pinot.
- Есть явная собственная система цветов, типографики, отступов и компонентов.
- Все ключевые страницы выглядят как одно целое на desktop и mobile.
- Динамический контент и админ-редактирование продолжают работать.
- Нет новых ошибок сборки; существующие предупреждения не увеличены без объяснения.
- Нет удаления/перезаписи данных, миграций или секретов без отдельного подтверждения владельца.

## 7. Что нужно уточнить у владельца до финального визуального решения

1. Финальное название бренда и допустимость слова «Террасы» как основной марки.
2. Главный бизнес-приоритет на ближайшие 6–12 месяцев: номера, дегустации, ресторан, мероприятия или винный магазин.
3. Есть ли фирменный логотип, брендбук, юридически разрешённые фотографии и требования к фотографам/изображениям.
4. Должен ли сайт быть RU-only или нужен EN-слой.
5. Какая фактическая система бронирования и какие действия разрешены на сайте: заявка, внешний переход, оплата.
6. Какие события/цены/контакты считаются актуальными источниками данных.

До получения ответов агент может использовать нейтральные placeholder-тексты и существующие данные API, но не должен выдумывать цены, награды, отзывы, географию или условия бронирования.
